# 国开 LMS 单课程视频播放器

提供一个 `https://lms.ouchn.cn/course/<课程ID>/ng#/` 链接，
程序通过页面控件播放该课程内的未完成视频。只处理你提供的课程。

## 启动

在本仓库目录执行：

```bash
.venv/bin/python scripts/run_ouchn_assistant.py "https://lms.ouchn.cn/course/10000118045/ng#/"
```

也支持：

```bash
.venv/bin/python -m ouchn_assistant.cli --course-url "https://lms.ouchn.cn/course/10000118045/ng#/"
```

无需填写课程 ID、活动 ID、专题名称或播放时长。
首次运行或登录失效时，在程序打开的 Chrome 中手动登录，
可扫码登录。程序最多等待 10 分钟，检测到目标课程目录就绪后自动继续，
不需要回终端按 Enter。每 30 秒提示一次等待状态。
若登录后进入 LMS 首页，程序会打开最初提供的课程链接。
后续复用独立 profile 的登录态。

尚未安装依赖时，需要 Python 3.12 和系统 Google Chrome：

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e .
```

仅查看筛选后的目录：

```bash
.venv/bin/python scripts/run_ouchn_assistant.py --mode inspect "https://lms.ouchn.cn/course/10000118045/ng#/"
```

## 运行流程

勾选“未完成” → 点击“全部展开”（已经展开时保持）→
读取可见未完成资源或视频 → 进入资源探查或点击第一个视频 →
等待自然播放结束 → 点击“返回课程” → 重新勾选“未完成” →
明确核对原视频的完成态 → 继续剩余视频。

视频以 1 倍速播放，不静音、不设置时间、不调用学习接口。
重新进入视频时，可由平台自身恢复上次播放位置。
视频结束与平台记录完成分别核对；不会以“观看到 80%”作为切换条件。
全部展开会同时展开专题和学习区，不依赖“核心学习”等特定名称。

外部引用资源会先进入探查：发现唯一可识别的视频才点击播放并等待自然结束；
没有视频时点击页面返回/关闭控件退出，不把打开资源推断为已完成。
多个可见视频、外部 iframe、跨到非国开页面或没有唯一退出控件时暂停并保留现场。
如果资源入口包含文件列表，会逐个打开引用文件；视频播放至结束，
文档、文本或可滚动文件滚动到底部后返回，再继续下一个文件。
未完成的文本页面会点击进入，使用页面滚轮逐段滚动到文档底部，
再点击返回课程；无法确认滚动到底部或页面包含可见视频时暂停。
文本页面已读到底但平台完成态延迟时，会记录“平台未确认”并继续其他活动，
不会把该状态伪装成平台完成。

勾选筛选、展开目录、进入视频、点击播放和返回课程前，
各自随机等待 0～3 秒，终端显示本次等待时长。
延迟后重新核对页面和弹窗；筛选已勾选、目录已展开或视频已播放时跳过点击。
操作串行执行，每次至多点击一次；点击结果仍由页面状态确认，不自动重复重试。
范围集中在 `src/ouchn_assistant/ui_actions.py` 的两个延迟常量中。
随机延迟只改变操作间隔，不能保证平台检测不到自动化。

## 暂停和退出

按 Ctrl+C 中断。本工具关闭自己启动的 Chrome 并释放 profile 锁。
重新提供同一链接后，以实时课程目录为准继续，不用旧检查点跳过活动。

以下情况会暂停并返回原因：播放器中途暂停、连续 60 秒无进展、
登录失效、确认弹窗、页面或播放器不匹配、速度不是 1 倍、
视频播放结束但平台在有限等待后仍未明确记录完成、
视频虽未完成但被平台锁定且需要先完成前置条件。
暂停时会在本轮运行目录保存 `pause.png` 和 `pause_diagnostics.json`，
并停止所有点击但保持 Chrome 现场；关闭浏览器或按 Ctrl+C 后才退出。
诊断文件记录当前阶段、活动、页面地址和可见弹窗文本，便于直接分析，
不需要先关闭浏览器再重新执行。
不会自动处理验证码、确认挑战、测验、作业或讨论。
同一 profile 不能同时运行多个本工具实例；不会自动删除残留锁或杀掉其他进程。

## 本地记录

Chrome profile 位于 `.runtime/chrome-profile/`，由 Chrome 保存登录态。
程序不导出密码、cookie 或请求头。
每次运行创建独立 `runs/<运行ID>/`：

- `activities_snapshot.json`：可见目录及观察到的全部节点完成态。
- `events.jsonl`：选中、播放、返回、确认、暂停等事件。
- `checkpoint.json`：当前活动、阶段和已观察结果。
- `assist_results.json`：运行是否完成、暂停或中断；分别记录播放结束与平台完成。
- 资源探查结果也写入 `assist_results.json`，包含视频资源和非视频资源的结果。

检查点把执行 `phase` 和终态 `status` 分开保存；结果保留 `last_phase`、
`error_type` 和具体错误原因。页面或浏览器关闭时停止执行，不自动重启。
最终记录写入失败会明确提示，并尽量保留原始异常。
退出清理失败会单独提示，保留原来的暂停或中断原因；
锁文件归属异常时不删除其他实例的锁。

`inspect` 模式只生成目录快照和事件日志。
旧 DOM 探查入口复用目录稳定读取，并保存活动元素 ID；
无法确认目录就绪时输出明确标为 `incomplete` 的诊断快照。

## 兼容性与验收状态

适用于相同国开 LMS 目录布局和可识别 HTML 视频播放器的课程。
课程链接、章节和活动动态读取；未知播放器或嵌入资源会暂停。
目录快照代表已展开 DOM 的稳定观察，不保证所有课程不存在延迟加载。
空课程或目录结构不匹配时暂停，不误报全部视频完成。
